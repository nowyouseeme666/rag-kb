# RAG（检索增强生成）技术详解

## 什么是 RAG

RAG（Retrieval-Augmented Generation）是一种将信息检索与文本生成相结合的技术架构。它通过在生成回答之前先从外部知识库中检索相关信息，将检索结果作为上下文提供给大语言模型，从而显著提高回答的准确性和可靠性。

## RAG 的核心流程

RAG 系统的工作流程分为两个阶段：

### 离线阶段（入库）
1. 收集文档资料
2. 将文档切分为适当大小的 chunk
3. 使用 Embedding 模型将每个 chunk 向量化
4. 将向量存入向量数据库

### 在线阶段（问答）
1. 接收用户问题
2. 使用相同的 Embedding 模型将问题向量化
3. 在向量数据库中检索最相似的 k 个 chunk
4. 将检索到的 chunk 和用户问题一起拼接成 prompt
5. 发送给 LLM 生成最终回答

## RAG 相比传统方案的三大优势

### 1. 降低幻觉风险
LLM 基于检索到的真实文档生成回答，而不是凭空编造。即使 LLM 的知识截止日期较早，也能回答最新的问题。

### 2. 知识可更新
无需重新训练模型，只需更新知识库中的文档即可。新知识入库后立即可用。

### 3. 可溯源
每个回答都可以追溯到具体的来源文档，便于事实核查和人工复核。

## chunk_size 的调优建议

chunk 大小的选择是 RAG 系统中的一个关键权衡：
- 太小的 chunk 可能丢失上下文信息
- 太大的 chunk 可能引入噪声
- 中文场景建议 500-1000 字符
- 需要根据具体文档类型进行实验调优

## Embedding 模型的选择

中文场景推荐使用 BAAI 系列的 bge 模型，如 bge-small-zh-v1.5 或 bge-large-zh-v1.5。这些模型在中文语义理解任务上表现优异。
